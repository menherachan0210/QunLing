# 性能审查（2026-10-24）

本次结合当前源码、服务器资源快照和已有请求诊断元数据审查。样本为 64 条记录，其中 58 条成功请求；来自同一部署且任务复杂度不一致，不能据此承诺固定回复时间。未读取或公开聊天正文、密钥及工具参数。

## 实际耗时

| 请求类别 | 成功样本 | 总耗时中位数 |
| --- | ---: | ---: |
| 无工具的明确请求 | 22 | 13.55 秒 |
| 仅查询工具（搜索、网页、群前文、识图、状态等） | 17 | 48.61 秒 |
| 包含生成、文件、漫画或写入等其他工具 | 19 | 60.81 秒 |

单次工具的执行中位数：搜索约 41.98 秒（11 次），识图约 14.07 秒（5 次），网页读取约 0.85 秒（14 次），群前文约 0.64 秒（20 次），群文件浏览约 0.38 秒（21 次）。这些是工具执行时间，不包含前后模型轮次或等待执行名额的时间。

成功请求中的工具排队累计最高约 109.7 秒；工具结束后重新获得模型名额通常不到 0.03 秒。一个约 101 秒的搜索请求中，两次搜索约用 66 秒，三次网页读取合计约 1.5 秒，其余主要是多轮模型与准备流程。带工具请求调用次数的中位数为 2 次，较长的达到 5 次以上。服务器快照未显示应用持续打满 CPU 或内存；这不是完整的负载测试。

## 本轮完成

原来所有工具共用一个执行名额、两个等待／执行位置。长时间生图、搜索或文件任务会阻塞其他成员的前文和状态查询，容量满时还可能直接拒绝新工具调用。

现在轻量读取、网络／视觉查询、一般任务各有独立容量。默认一般任务仍串行；网络／视觉查询最多 1 个；轻量读取最多 2 个。每条通道最多停放 2 个请求，整体仍有上限。同一请求的先后依赖、模型并发额度、授权验证、取消和不确定交付语义不变。文件状态查询只有明确不等待时才进入轻量通道，下载或导入仍进入一般通道。

回归验证覆盖：长任务占满时其他请求仍能搜索和读前文、每条通道取消后的容量归还、排队时权限撤销、操作参数改变、同一成员的请求顺序及原有任务可靠性。测试使用合成请求，不向真实 QQ 群发送消息。这项改动减少跨请求阻塞，不会直接缩短上游搜索或生成的执行时间。

## 优化方向与当前进度

| 优先级 | 位置 | 可优化内容 | 验证要求 |
| --- | --- | --- | --- |
| 已实现，待线上测量 | QQWebSearch 与 Agent 工具循环 | 单次最多读取四个已确定的来源，最多两个并发；保留分页、来源状态和每轮预算 | 部分失败与证据范围已有回归；线上继续对比模型轮次与端到端耗时 |
| 高 | 搜索服务 | 单独测量搜索模型首包、搜索执行和摘要输出时间，比较简短事实查询与深入研究的成本；检索力度由模型理解任务决定 | 同题对照准确性和来源质量，不能仅靠砍超时或取消查证提速 |
| 已实现 | LongTermMemory 与 LocalAgent RAG | 本轮注入成功后，按请求身份、问题和知识库匹配，移除同一次运行的重复自动检索选择 | 已验证失败时保留原检索、配置不被持久修改；保留知识库授权、说话人归属和群范围 |
| 中 | LocalAgent 上下文预算 | 同一轮多次计算相同消息的 token 数，可考虑有界缓存或合并计数 RPC；整理冗余上下文 | 使用完整输入及模型设置区分缓存；保持原计数精度，不丢当前问题、原图引用或关键记忆 |
| 中 | 群图片理解 | 复用同群已有观察，确有新问题或新图再识别；同批独立图片可合并理解 | 原始像素、图片版本、提问与权限范围必须一致，不能把旧观察冒充本轮新识图 |
| 已实现，继续采样 | 诊断管理页 | 展示请求阶段与工具耗时、自由对话近一小时判断/生成/核对的中位数及 P95 | 只保存有限元数据；截断记录明确标记；线上继续区分首个有用回复与最终交付 |

暂不建议简单增加所有工具并发、缩短超时后直接报错、降低全部模型质量，或用自动“处理中”提示代替实际提速。用户已要求减少无用提示。独立任务可以并行，存在依赖或外部副作用的操作仍需按正确顺序执行。

## 2026-10-25 实施与测量口径

已加入持久网页/搜索复用、回答前本地检索、按指定来源定时采集、单次多页读取、独立参与判断模型、解析结构复用和后台诊断写盘。检查到 MemoryInjector 与 LocalAgent 的自动 RAG 重复路径：完成本轮注入后只移除本次自动检索选择，不移除知识库授权。

可重复的离线证据：同范围相同搜索两次只调用一次搜索替身；实时要求与跨成员请求仍分别调用；3 个不同页面含一个失败来源最多同时读取 2 个，成功页只标记实际返回的范围；真实 DOCX 在独立解析子进程完成检查后，再搜索时命中结构缓存。慢诊断存储在后台线程等待时主事件循环可以继续运行。相关回归见 `test_web_knowledge.py`、`test_document_cache.py`、`test_journal_writer.py` 与 QQWebSearch 的 `test_knowledge.py`。

这些结果证明减少重复调用及解析的机制，不代表线上延迟下降了某个百分比。独立判断模型由管理员选择，模型质量和速度需实际观察；没有删除判断、回复核对或权限检查来换取速度。管理页现在可查看请求阶段耗时、自由对话近一小时中位数/P95、知识库命中与采集计数。后续按相同类型问题比较命中/未命中样本，分别记录首个有用回复与最终交付时间。
