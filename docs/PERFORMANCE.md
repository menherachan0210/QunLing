成功请求中的工具排队累计最高约 109.7 秒；工具结束后重新获得模型名额通常不到 0.03 秒。一个约 101 秒的搜索请求中，两次搜索约用 66 秒，三次网页读取合计约 1.5 秒，其余主要是多轮模型与准备流程。带工具请求调用次数的中位数为 2 次，较长的达到 5 次以上。服务器快照未显示应用持续打满 CPU 或内存；这不是完整的负载测试。

## 本轮完成

原来所有工具共用一个执行名额、两个等待／执行位置。长时间生图、搜索或文件任务会阻塞其他成员的前文和状态查询，容量满时还可能直接拒绝新工具调用。

现在轻量读取、网络／视觉查询、一般任务各有独立容量。默认一般任务仍串行；网络／视觉查询最多 1 个；轻量读取最多 2 个。每条通道最多停放 2 个请求，整体仍有上限。同一请求的先后依赖、模型并发额度、授权验证、取消和不确定交付语义不变。文件状态查询只有明确不等待时才进入轻量通道，下载或导入仍进入一般通道。

回归验证覆盖：长任务占满时其他请求仍能搜索和读前文、每条通道取消后的容量归还、排队时权限撤销、操作参数改变、同一成员的请求顺序及原有任务可靠性。测试使用合成请求，不向真实 QQ 群发送消息。这项改动减少跨请求阻塞，不会直接缩短上游搜索或生成的执行时间。

## 下一步优先级

| 优先级 | 位置 | 可优化内容 | 验证要求 |
| --- | --- | --- | --- |
| 高 | QQWebSearch 与 Agent 工具循环 | 一次读取多个已确定的独立来源，减少“读一页—问一次模型”的往返；保留分页、来源状态和每轮预算 | 对比模型轮次与端到端耗时，验证部分来源失败、引用与证据完整性 |
| 高 | 搜索服务 | 单独测量搜索模型首包、搜索执行和摘要输出时间，比较简短事实查询与深入研究的成本；检索力度由模型理解任务决定 | 同题对照准确性和来源质量，不能仅靠砍超时或取消查证提速 |
| 中 | LongTermMemory 与 LocalAgent RAG | 注入器和 Runner 都存在自动检索路径，检查同一轮是否重复检索相同记忆；可在授权不变时共享本轮结果 | 先补调用级计时，保留知识库授权、说话人归属和群范围；不能删授权列表来跳过重复检索 |
| 中 | LocalAgent 上下文预算 | 同一轮多次计算相同消息的 token 数，可考虑有界缓存或合并计数 RPC；整理冗余上下文 | 使用完整输入及模型设置区分缓存；保持原计数精度，不丢当前问题、原图引用或关键记忆 |
| 中 | 群图片理解 | 复用同群已有观察，确有新问题或新图再识别；同批独立图片可合并理解 | 原始像素、图片版本、提问与权限范围必须一致，不能把旧观察冒充本轮新识图 |
| 后续 | 诊断管理页 | 按准备、模型、工具排队、工具执行、发送汇总耗时，区分首次可用回复与最终交付 | 只记录时间及有限元数据；失败请求和长任务单独统计，避免平均数掩盖长尾 |

暂不建议简单增加所有工具并发、缩短超时后直接报错、降低全部模型质量，或用自动“处理中”提示代替实际提速。用户已要求减少无用提示。独立任务可以并行，存在依赖或外部副作用的操作仍需按正确顺序执行。
