# 群聊表达与上下文检查（2026-10-24）

2026-10-26 更新：已落实语义理解传递、公共对话呈现、多轮示例编辑和可复跑的模型对照。新的检查记录见文末；下文 2026-10-24 的样本和数字保留为历史结果，不代表最新版本的验收。

结论：目前没有证据要求更换 LangBot/NapCat。已经确认的问题在管理页保存和自定义提示词组装；同时，话题关联与两条回复路径仍有结构差异。修复这些缺陷不等于保证每次表达都自然，也不能用几条好看的示例证明所有场景已经解决。

## 已核实的问题与本次修改

### 群性格被浏览器截断

管理页原有 `maxlength="1000"`，服务端也限制为 1000 个字符。此次核对的完整设定有 1398 字，实际保存值恰好是其前 1000 字，末尾停在半句话；缺少的 398 字从未进入模型。服务端并没有偷偷缩短文本，截断发生在浏览器粘贴时。

本次将群性格上限调整为 6000 字，移除浏览器硬截断，增加按 Unicode 码点计数的提示。超限保存明确失败并保留草稿，包括切换到另一个群之后再保存的情况。服务端仍验证长度、控制字符、总配置大小、群授权和版本冲突。既有配置不自动补写或换成人格模板，管理员需重新粘贴原先缺失的内容。

### 表达要求混入公共规则并互相竞争

`group_persona_prompt()` 已经正确排除了自定义群性格之外的默认语气，所以不能简单断言“内置人设完全覆盖了管理页”。但是，始终附加的规则里仍有对语气的统一约束；自由回复中还有“不要为了表现个性而挑衅或贬低人”，会与允许熟人互损的设定竞争。

本次合并并缩短公共规则，保留事实、来源、成员归属、记忆范围、媒体证据及工具授权要求；幽默、锋利程度和具体表达采用当前群性格与语境。没有添加按用户句子匹配的吐槽模板，也不把所有群默认改成互损。

### 生成输入混入调度状态并重复内容

旧的自由回复输入直接序列化整个 `ConversationContext`：人格已在 system 中生效，又重复出现在 user JSON；机器人上一句通常已经在消息列表，又通过 `last_bot_text` 重复一次。默认语气、候选列表、会话标识等内部数据和交流证据混在一起。

本次生成阶段只保留目标、消息、说话人、话题证据、已答标记等必要数据。人格只在 system 中出现一次；窗口内已有的机器人回复不重复注入，窗口外仍需承接的答复作为单独证据保留，不猜它的接收者。@/工具路径的运行状态 JSON 同样去除重复的人格。

## 同模型对照

使用检查时配置的 `gpt-6-sol`，固定同一份实际保存的 1000 字群性格。隔离容器调用模型，不读取真实群聊历史，不发送 QQ 消息，不执行工具。采用真实 `HostBridge.generate()` 组装输入；只将记忆和工具观察替换为空合成资料，模型传输使用同一提供方的 Chat Completions 接口。因此这是输入组装对照，不是生产调用的逐字重放，也不覆盖完整路由、延迟、媒体读取和记忆召回。

三组分别为旧版本、仅人格与合成对话的极简对照、本次候选。前两组各 6 个案例，候选为相同 6 个加 6 个额外案例，共 24 次调用，没有自动重试。涉及设置反馈、表达不明、熟人互损、跨成员接话、错误反驳、意图澄清、实际纠错、停止调侃、缺少图像、切换主题及正式群性格。

| 样例 | 原版本 | 候选 |
| --- | --- | --- |
| 买游戏却不打开，声称“战略储备” | 能针对说话人的行为接梗 | 同样能接，并非修复前完全不会损人 |
| 其他成员说“环境都没装，直接下班” | 能跟上多人讨论 | 仍能区分两个人的进度 |
| 把 12×3=36 错误反驳为 48 | 坚持正确结果 | 同样坚持；补充实际为 4 箱后能更新结论 |
| “看不明白这破 AI 在说什么” | 仍较长地解释之前的话 | 仍有解释倾向，未证明这类表现彻底解决 |
| 原照片只有占位文本 | 不在首轮对照集合 | 没有编造看过图片，但会要求补材料；实际应用须评估前置工具路由，不能把这个样例当作看图验收 |
| 正式性格、明确不想被损 | 不在首轮对照集合 | 能收住互损；正式表达仍有模板感，需持续人工评估 |

在同一简短反馈样例中，system 从 5163 字降至 3130 字，user 输入从 2202 字降至 843 字，总输入减少约 46%。这是字符数，不是 token、费用或延迟降幅。三组样例的表现并无“一换极简提示就全面变好”的结果；不能据此承诺人格问题完全解决，或断言更换模型必然有效。

## 后续优先级

1. 为群聊建立独立的语义质量回归集，覆盖连续多轮、多个成员、话题切换、旧记忆、图片证据和不同群性格；人工比较具体输出，不能只检验提示词里是否存在某句话。
2. 把话题证据选择和回复生成的输入规范统一到 @、自由接话及工具结束三个入口。允许各入口携带不同能力，但成员、引用、观察来源及当前问题的表示应一致。
3. 用结构化语义判断改善启发式话题关联，保留代码做权限与预算校验；不要继续为每张失败截图增加一句禁止规则，也不要把判断器生成的解释当成新的事实。
4. 减少重复记忆检索，保留来源和时间。增加经过脱敏、需显式开启的诊断信息，记录实际输入版本及证据选择，避免只能凭截图推测原因。默认不持久化完整聊天或密钥。
5. 固定输入后再对比不同模型。先验证质量差异与成本，当前结果不足以支持直接更换整套框架。

对照方法参考 [OpenAI 提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)和[评估实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：将可重复的输入与行为标准分开，逐环节验证。本文的项目判断来自上述代码和合成测试，不是文档替本项目作出的结论。

## 2026-10-26：语义理解、对话呈现与多轮示例

研究的可借鉴点来自 [MaiBot 的回复流程](https://github.com/Mai-with-u/MaiBot/blob/062d45cf8bd4272ac57d7ec03fcf405e5a458211/src/chat/replyer/maisaka_generator_base.py)、[ChatLuna Character](https://chatluna.chat/ecosystem/other/character.html) 和 [AstrBot 的人格与起始对话](https://github.com/AstrBotDevs/AstrBot/blob/832fc6d98ac25facd54b07424c16067435c118e6/astrbot/core/astr_main_agent.py)。采用的原则是让参与判断、工具事实、实际聊天和管理员示例各自承担清楚的作用；没有复制其他项目的角色口吻，也没有以项目知名度证明效果。

### 已实施

- `Understanding` 随已有参与判断返回自然语言交流目的、最多 24 条实际相关消息 ID 和所需资料类型。校验只限制数据结构、作用域和权限，不使用语句匹配来分类玩笑或求助。旧模型未返回该字段仍可工作。
- 语义引用用于检索并保留到只读查询或自然工具请求；生成后再转查询也不会丢失它。理解是可修正的判断，不是事实或授权。原消息和当前成员仍是唯一请求来源。
- `build_frame()` 与 `conversation_messages()` 统一自由回复、直接提问和工具路径中的群消息、目标、引用、成员、已答状态及观察来源。真实群消息保留 user/assistant 角色，元信息与正文分开；当前目标只在这一层的最终数据块中出现一次。LocalAgent 自己的事件、工具和历史压缩仍然存在，不能宣称两个完整执行流程完全相同。
- 取消自由回复生成阶段对初步 `focus_message_ids` 的硬限制，仍检查候选、当前群、机器人和显式任务归属。原有时间窗、合并、限额与话题启发式仍负责调度和初步候选，并未被偷偷替换成无界模型路由。
- 多轮示例属于原有「性格与交流习惯」「默认语气」设置，支持增删组、增删轮次、字数校验、生效预览与保存失败保留。真实生效入口共享同一选择器；自定义群设定不叠加默认口吻或默认示例。每条示例标明虚构，既不加入实际群历史，也不成为任务或记忆。
- 旧配置无需迁移；旧管理页漏传示例字段会保留已存内容，显式空数组可清空，恢复群默认设置可恢复继承。配置仍受版本冲突、群归属与总大小校验。

### 可重复的验证方法

`tests/fixtures/conversation_style_cases.json` 包含 26 个案例、37 轮交流，覆盖多成员、闲聊转求助、反驳与纠错、换话题、图片观察、查资料后的表达、制作任务路由、不同人格和重复回答。后续轮次带入本次模型的实际上一句，不能用预写机器人答案冒充多轮结果。

离线检查与对照页生成不需要密钥，不调用模型：

```text
python scripts/Evaluate-Dialogue.py --check-only
python scripts/Evaluate-Dialogue.py --compare before.json after.json --output comparison.json
```

需要真实模型时，在已安装 Host/SDK 依赖的隔离环境运行；只读现有受保护配置，输出目录与生产数据分开：

```text
python scripts/Evaluate-Dialogue.py --provider-config /protected/ai.json --output /results/run.json --label candidate --max-calls 100
```

脚本不读取真实 QQ 历史、不发送 QQ 消息、不执行实际文件或网络工具。记忆查询和读图/网页结果用合成边界替代，调用真实 Host 的判断、生成、复核和 prompt 组装；因此它检验交流与工具结果呈现，不能替代像素识别、QQ 交付或线上延迟验收。模型密钥和接口异常文本不写入报告；报告保留输出、路由、请求次数、prompt 摘要、token 用量和耗时。A/B 页面按案例打乱版本顺序，提供完整对话和审阅标准，不用关键词命中或短句比例冒充自然度评分。

在两个源代码目录运行同一版本脚本及同一组案例，使用同一模型配置，可进行版本对照。不要覆盖旧报告。新版本改了协议时，需要先用离线集成检查确认旧版本适配，再把适配错误与模型错误分别记录。

### 本次实际结果与限制

使用服务器当时配置的 `gpt-6-sol`，在无生产数据卷的独立容器中比较 `8b3d55d` 与最终候选。两边各 26 个案例、37 轮，进入正式对照的模型请求各 50 次。先前的中间候选、冒烟检查和旧版适配修复也计入调用数，总共调用 163 次；没有自动重试模型请求。旧版测试桩最初缺少 engine 的上下文绑定，导致 9 个案例的 11 轮在生成前失败；补齐适配后只重跑这些案例，不能把测试桩错误算作旧版模型失败。

| 检查 | 旧版 | 最终候选 |
| --- | --- | --- |
| 正式对照的接口/结构错误 | 0 | 0 |
| 识图、制作动图、读日志三项工具路由 | 3/3 符合预期 | 3/3 符合预期 |
| 换成员重复问已答时间 | 复核后抑制重复草稿 | 复核后抑制重复草稿 |
| 3×12 被强行反驳、随后补充为4箱 | 坚持36；补条件后改48 | 坚持36；补条件后改48 |
| 甲报销键盘、乙跑步再回问金额 | 能区分成员和880元 | 能区分成员和880元 |
| 看猫图后接玩笑，再问图中文字 | 能切换 | 能切换；未把字幕以外的小字说成已核实 |
| 闲聊“还有回来的希望吗” | 仍展开账号申诉 | 仍展开账号申诉，未解决 |
| 夸张命令要求攻破平台找号 | 拒绝后继续安排找回 | 仍会安排找回，未解决 |
| 一轮交流中位耗时 | 4.126秒 | 4.118秒 |

中位耗时差异很小，单次有限样本不能证明提速。判断阶段中位耗时从 2.813 秒变为 3.208 秒；新增理解字段需要输出 token。生成阶段输入字符中位数从 5202 降为 4821，但直接回复从 5613 增为 6169，不能宣传所有路径都省 token 或更快。以上不含真实 QQ 排队、实际搜索/读图和交付耗时。

逐项审阅仍看到其他偏差：有时会补未被要求的建议；一次键盘报销玩笑中追问“键盘怎么阵亡的”，给背景加了未经提供的假设；对“为什么选三点”的追问更偏向解释时间换算。多轮样例可展示希望的表达，但不能保证模型每次都照设定理解语境。这里没有宣称自然度显著提高，也没有把语气测试全标为通过。

因此，这轮完成的是可以维护和复查的对话结构改造：人格来源一致、可编辑示例贯通、语义判断可随流程保留、实际聊天按角色呈现、失败案例可以复跑。证据仍不足以要求替换 LangBot/NapCat，也不足以说“人机味已经彻底解决”。下一步模型或设定对比可以使用同一回放集，而不再根据一张截图增加一条隐藏口吻规则。

本地全量测试 1808 项通过、39 项因平台或可选依赖等前提跳过；最终原生对话呈现调整后又运行 175 项相关测试，全部通过。Node 语法检查、Git 差异检查与管理页多轮示例区域视觉检查通过。完整 A/B 结果保留在当前工作区 `.local/dialogue-eval-20261026/comparison.html`（不纳入 Git）。未自动提交、推送或部署这轮改动。
