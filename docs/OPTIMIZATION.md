# 全项目优化执行记录

目标：在保留多人归属、工具授权、资料时效和交付确认的前提下，减少重复检索、模型往返和文件解析，并补齐验证与管理体验。

## 实施与验收

- [x] 测试：自动发现全部根目录测试，明确普通/SDK 环境；镜像 CI 运行全部根目录和六个插件测试。
- [x] 诊断：明确请求与自由对话的分阶段耗时、调用次数和缓存命中；管理页展示；诊断写盘使用有界后台队列。
- [x] 联网资料：按权限隔离的持久资料、来源与时间、过期规则、本地检索及联网回填；支持管理员配置来源、周期、预算的后台刷新。
- [x] 网页读取：一次请求最多读取四个已知来源，最多两个并发，保留去重、独立错误和原有阅读状态/预算。
- [x] 自由对话：可独立配置判断模型，保持回复模型、工具转接与去重语义；完成本轮记忆注入后避免相同记忆再次自动检索，显式检索授权不变。
- [x] 文件：复用 PDF、DOCX、XLSX、PPTX 解析结构；权限、格式、解析限额及内容共同决定可否复用；密码和压缩包内文件不持久复用；大块文件读写移出主事件循环。
- [x] 发布：实现按提交发布应用/更新器镜像的 CI，以及校验来源、提交、平台、摘要的拉取更新路径；保留源码构建与现有备份/恢复。
- [x] 配置：管理员主动触发的聊天、视觉、联网、图片能力测试，分项结果/耗时，明确计费并避免相同请求重复调用。
- [x] 维护：知识库、网页服务、缓存、诊断、镜像解析、自检均提取独立模块；同步 README、架构、运维和开发说明。
- [x] 验证：完成离线和固定 SDK 回归、七个插件实际打包、发布文件检查及浏览器页面检查；外部验收边界如下。

## 原则

- 知识检索在决定回复后执行；资料不足、过期或用户要求核实时仍可联网。
- 不把搜索摘要、已保存网页与本次实际读取混淆；保留引用与证据范围。
- 后台采集独立限额、租约和失效检查，不占满前台能力，不向 QQ 自动发消息。
- 私聊、成员资料与公共网页分开存储；缓存命中不能授予新权限。
- 不自动重试结果不明的计费调用或发送，不删除现有业务数据。
- 性能收益以计数和测量为依据，不把合成回归当作线上吞吐验收。

## 外部验证边界与启用方式

- 本机没有 Docker，未运行 Linux 镜像、Compose 初始化/升级/回滚验收。CI 已配置这些检查，镜像只在主分支全部检查通过后发布；本次没有推送代码或发布镜像。首次发布后需确认 GHCR 包可公开拉取。
- 原生 7-Zip 下载受网络连接影响，部分压缩包回归未执行；其他平台条件也会跳过相应测试。CI 镜像提供固定 7-Zip 并重新执行完整测试。
- 没有调用真实付费模型、联网搜索服务或向 QQ 发送消息。模型能力自检、独立判断模型的效果及线上延迟需在实际部署中主动验收。
- 知识库默认允许复用，订阅来源初始为空；管理员在「资料知识库」中填入群号、公开 URL、刷新间隔、有效期及每日预算后才会定时采集。暂用有界关键词检索，不依赖向量模型；登录页、脚本渲染页和未命中资料仍可能需要其他读取或联网工具。
- 自检入口位于「AI 服务 → 测试已保存的 AI 能力」，只有主动提交并确认费用才调用服务；图片项检查生成能力，不代表图片编辑已验收。
- 更新镜像模式、首次部署的摘要固定方式见 [运维文档](OPERATIONS.md)；已保存的知识库和解析结果位于现有数据目录。
