# QQ 功能与工具联动

QQGroupContext 0.3.0 增加 `qq_capabilities`（分类目录和参数）与 `qq_action`（执行）。模型根据当前对话语义选择功能，不依赖命令词或正则匹配。`@` 对话和已开放的自由对话使用同一套工具。

| 类别 | 能力 |
| --- | --- |
| 查询 | 当前群资料、成员、荣誉、公告、精华、禁言成员、@全体额度、文件容量与目录、消息及媒体、最近平台事件、申请、账号状态；机器人管理员可查好友列表 |
| 互动 | 戳一戳、表情回应、资料点赞、内置表情、骰子、猜拳、文字、引用、@成员、合并转发 |
| 管理 | @全体、撤回、禁言与解除、移出成员、全员禁言、群名、名片、头衔、管理员任免、公告、精华、申请处理、退出当前群 |
| 文件 | 创建、删除文件夹，删除、移动、重命名文件，上传工作区素材到指定群目录 |
| 媒体 | 导入 QQ 图片、语音、视频和附件；QQ 角色语音；语音识别；视频抽帧和实际视觉分析；发送图片、语音和视频 |

已有的群前文、头像、图片/GIF、附件、搜索和文件工作区工具继续使用。素材统一为 `asset_ref`，例如搜图 → 导入 → 合成 GIF / 打包 ZIP → QQ 发送，或收到视频 → `media` → `import_media` → `video_frames` → `analyze_images`。返回素材编号不代表已识别内容。

## 管理页

群聊设置的 **QQ 工具** 页签提供本群的互动、管理、文件整理、媒体开关，以及机器人全局的扩展工具开关、管理员 QQ 号与语音识别模型名。原有配置兼容载入；旧版管理页保存不会清掉这些字段。恢复群默认性格与参与方式保留 QQ 工具权限。

机器人管理员为空时，账号级操作不可用。群管理员可管理本群，但不能借机器人权限执行自己无权发起的操作。管理员任免和头衔要求机器人实际为群主。机器人是群主时拒绝直接退出，避免解散群。

语音识别模型名由管理员填写，复用聊天提供商的地址和凭据，要求支持 `POST /audio/transcriptions`。未配置或服务不兼容时返回明确错误。QQ 角色语音使用 QQ 返回的角色编号，不依赖该识别配置。

## 执行与边界

- 群、机器人、发言者、工作区从当前 Host Query 解析，模型不能覆盖。消息归属和成员身份通过 QQ 查询核验；文件、目录、公告与语音角色使用本轮实际读取的编号。
- 普通自由接话可以查询和选择轻量互动；群管理、媒体发送及文件写入通过实际任务意图进入操作流程。引用、网页、文件内容和玩笑不构成管理授权。对话语气仍来自群性格与默认语气。
- 写操作先持久登记，再调用 QQ。未知结果不重试；同一请求同一操作去重，申请处理跨对话去重。每轮最多 6 次写操作，每个会话每分钟最多 12 次。
- 事件仅保存接入后实际收到的通知；当前对话可读近十分钟事件，工具可查最近 24 小时。通知作为资料，不自行制造用户请求。清群记忆会清事件内容，但保留防重复的操作回执。
- 视频最多导入 20 MiB、抽取前 120 秒内最多 8 帧；抽样不是逐帧理解，也不包含声音识别。FFmpeg 在容器内解码，限制时限、线程和输入协议。
- QQ 角色语音、表情回应、群管理等仍取决于 NapCat 版本与账号权限。此集成覆盖聊天及机器人操作能力，不包含 QQ 音视频通话、屏幕共享或 QQ 空间等完整客户端功能。

协议依据：[NapCat 4.18.37 接口](https://napneko.github.io/api/4.18.37)、[NapCat 消息类型](https://napneko.github.io/develop/msg)、[音频转录接口](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)。

离线回归在 `tests/test_qq_actions.py`、`test_qq_gateway.py`、`test_qq_media.py`、`test_qq_events.py` 中覆盖真实工具入口、接口参数、权限与会话隔离、超时去重、素材联动和短视频抽帧，不向真实 QQ 发送测试消息。
