# QunLing

给 QQ 群聊和私聊接入自己的 AI。基于 **LangBot + NapCat**，带群聊上下文、记忆、识图、生图改图、文件阅读、漫画翻译和联网工具。群内还可按需查询成员资料、识别头像、浏览群文件，以及阅读合并转发的聊天记录，示例见[功能与使用](docs/FEATURES.md)。

新部署只需：**启动 → 填 AI 服务 → QQ 扫码登录**。插件、模型关联、记忆库、触发规则和 QQ 连接由设置页自动配置，无需逐个安装插件或填写 WebSocket。文件解析依赖、7-Zip 和后台文件任务进程随部署自动准备。

## 快速开始

Windows 与 Linux 使用同一套 Linux amd64 容器。建议预留 **8 GiB 内存、10 GiB 可用磁盘**；更新备份还需要额外空间。首次构建需下载依赖、官方 QQ 容器和本地记忆模型，网络应能访问 GitHub、Docker Hub、PyPI 及模型下载站点。

### Windows：双击启动

本节用于**让机器人运行在 Windows 本机**。如果只是用 Windows 电脑管理已部署的 Linux 服务器，请直接看下方“服务器管理页”，使用 SSH 隧道访问服务器。

1. 安装并启动 [Docker Desktop 的 Windows x86_64 版本](https://docs.docker.com/desktop/setup/install/windows-install/)，启用 WSL 2，使用 **Linux 容器**。WSL 安装、虚拟化和 Docker 设置的操作见 [Windows 完整部署教程](docs/WINDOWS.md#1-准备-wsl-2-和-docker-desktop)。
2. [下载项目 ZIP](https://github.com/menherachan0210/QunLing/archive/refs/heads/main.zip)，**完整解压**到固定目录，例如 `D:\Apps\QunLing`。进入能看到 `Start-Bot.cmd`、`scripts`、`deploy` 的那一层；不需要另装 Git、Python、QQ 客户端或 7-Zip。
3. 确认 Docker Desktop 的引擎已经运行，再双击 **`Start-Bot.cmd`**。首次需要下载、构建镜像并安装插件，请等启动完成；构建途中不要关闭窗口。
4. 成功后会自动打开带令牌的设置页；没有自动打开时，双击 **`Open-Bot.cmd`**。本机部署不需要 SSH 隧道。插件就绪后填写 AI 服务并扫码登录 QQ，页面显示“机器人已连接”后即可使用。
5. 以后先启动 Docker Desktop，再用同一目录的 `Start-Bot.cmd` 启动。`Open-Bot.cmd` 用于重新打开设置页，`Stop-Bot.cmd` 用于停止并保留数据。成功启动后可以关闭命令窗口和网页，Docker Desktop 仍需运行；电脑关机或休眠时，本机机器人无法继续在线。

可以在 **CMD 或 PowerShell** 先检查环境：

```text
docker compose version
docker info --format "{{.OSType}}/{{.Architecture}}"
```

第一条应正常显示 Docker Compose 的版本号，第二条应显示 `linux/x86_64` 或 `linux/amd64`。若报错，先按 [Windows 排障说明](docs/WINDOWS.md#6-常见问题)处理，再启动项目。

需要手动查看专属链接时，在**项目根目录**打开 CMD 或 PowerShell，执行：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Public-Bot.ps1" -Action url
```

复制输出的完整 `http://127.0.0.1:5310/#token=...` 链接打开。若页面只显示“设置令牌”，可以重新双击 `Open-Bot.cmd`，或把 `#token=` 后的字符串填入令牌框并点击“连接”；不要填写 AI API Key。

仅支持运行 Linux amd64 容器的环境；Windows ARM 和 Windows 容器模式不在当前部署支持范围内。已有旧版本机 `langbot/.venv`、`napcat/` 环境的目录仍走兼容启动逻辑，不会自动改为容器或迁移历史。完整的首次设置、启停、网页更新、日志与常见错误处理见 **[Windows 完整部署教程](docs/WINDOWS.md)**。

### Linux：服务器部署

先通过 `ssh 用户名@服务器IP` 登录服务器，安装 [Docker Engine](https://docs.docker.com/engine/install/) 与 [Compose v2](https://docs.docker.com/compose/install/linux/)，然后**在服务器终端**下载源码并启动：

```bash
git clone https://github.com/menherachan0210/QunLing.git
cd QunLing
bash bot.sh up
```

也可以解压同一个 ZIP 后在目录中执行 `bash bot.sh up`。如果当前用户没有 Docker 权限，改用 `sudo bash bot.sh up`。启动结束会显示包含 `#token=` 的专属设置链接；打开方法见下一节。

### 服务器管理页：获取带令牌的链接

**第一步：在自己的电脑上建立 SSH 隧道。** Windows 可以打开 CMD 或 PowerShell，macOS／Linux 打开终端，将用户名和服务器 IP 换成自己的：

```text
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:5310:127.0.0.1:5310 用户名@服务器IP
```

使用密码登录时，输入过程中不会显示字符，输完按回车即可。连接成功后窗口保持等待是正常的，**保持此窗口打开**。这条命令只负责端口转发，不会显示设置令牌；已有同端口的 SSH 隧道时直接复用，无需重复建立。

**第二步：在电脑上再开一个终端，获取专属链接。** 下面以服务器项目目录为 `~/QunLing` 为例；其他安装位置请修改 `cd` 后的路径：

```text
ssh -t 用户名@服务器IP "cd ~/QunLing && sudo bash bot.sh url"
```

如果已经在服务器终端，也可以进入项目目录后直接执行 `sudo bash bot.sh url`。有 Docker 权限的用户可以省略 `sudo`。获取链接不需要重新部署或重启机器人。

命令会输出类似下面的地址（这是格式示例，令牌以你自己的命令输出为准）：

```text
http://127.0.0.1:5310/#token=YOUR_SETUP_TOKEN
```

**第三步：复制完整链接，在自己电脑的浏览器打开。** 必须包含 `#token=` 及其后面的内容。页面解锁后再填写 AI 服务、扫码登录 QQ；SSH 隧道窗口继续保持打开。

如果只看到“打开专属设置链接／设置令牌”，说明当前页面没有通过认证。重新获取并打开完整链接，或把链接中 `#token=` 后面的字符串填入“设置令牌”，点击“连接”。这里填写的是自动生成的管理令牌，不是 AI API Key 或服务器密码。本机 Windows 容器部署直接双击 `Open-Bot.cmd`，也会自动打开带令牌的链接。

页面读取专属链接后会从地址栏移除令牌；重新打开普通地址仍可能要求认证，可再次使用原专属链接。请私下保存完整链接，不要发到公开聊天、Issue 或截图中。

### 完成设置

1. 填写 AI 的 **API 地址、API Key、聊天模型名、图片模型名**。视觉和联网使用不同模型时，展开额外选项填写。
2. 保存配置，用手机 QQ 扫描设置页的二维码并确认登录。
3. 页面显示连接成功后，在群聊中 **@机器人** 或发送 **`/ai 问题`**；私聊直接发送。

机器人 QQ 需先加入对应群。登录过期时回到设置页重新扫码。设置链接含管理令牌，请勿公开分享。

构建失败后修复网络再用同一入口重试，已完成的构建层会复用；不需要删除数据卷。小内存机器应留意任务执行时的占用，swap 不能替代推荐内存或保证多图、漫画任务并行运行。

## AI 服务需要支持什么

本项目不附带模型或额度。可填写兼容服务或自己的网关；模型名以服务实际提供的为准。

| 功能 | 服务需要提供的能力 |
| --- | --- |
| 对话、工具选择、记忆操作 | Chat Completions，支持工具调用 |
| 直接看图、群历史图片、漫画翻译 | 聊天模型支持视觉；历史图片与漫画也可指定独立视觉模型 |
| 生成／编辑图片 | Images generation / edits，编辑需支持多张参考图 |
| 联网搜索 | Responses API 的 `web_search`；可单独指定联网模型 |
| 长期记忆向量检索 | 已内置本地 Chroma 模型，不需另填嵌入 API |

所有模型默认共用一套地址与密钥，更换配置时向导会同步到相关插件。**仅有聊天接口的服务，不能自动获得图片和搜索能力。** 保存配置不调用模型；“连接成功”表示 QQ 与机器人连通，接口能力仍以首次实际使用为准。

## 能做什么

| 能力 | 自然语言示例 |
| --- | --- |
| 理解多人讨论与前文图片 | “他们刚才说的几部漫画，你更推荐哪部？” |
| 当前／引用／历史图片理解 | “上面两张介绍都说了什么？” |
| 生图、多图编辑 | “把这两张里的角色合到一张，背景换成咖啡店。” |
| 长期记忆 | “记住我更喜欢短篇。”／“忘记刚才那条偏好。” |
| 文件阅读、检索与整理 | 上传 TXT、PDF、DOCX、XLSX 或 PPTX 后说“对比两份资料，把差异整理成表格。” |
| 生成并发送附件 | “把刚才已有的译文整理成 TXT 发来。”／“把这些数据做成 Excel。” |
| 图片／漫画包翻译 | 直接发图片，或上传 ZIP、RAR、7z 后说“翻译成中文，给我 LabelPlus TXT。” |
| 加密压缩包 | 上传后说“密码是 xxx，读取／翻译这个包”；缺少密码时可补充，输错后可改正重试。 |
| 联网、多来源读网页、找现成图片 | “查查这件事的来源，对比原文。”／“找张帝企鹅照片发来。” |
| 查找并发送公开文件 | “把官网的 PDF 发来。”／“找到这个字体文件传上来。” |

功能按意图调用，没有必须背下来的绘图、阅读或联网口令。默认普通群消息不会触发回复；每次提问固定自己的上下文边界，后来的消息不会顶替正在回答的问题。

### 可选：让机器人自然参与群聊

在管理页打开 **自由对话**，读取已登录 QQ 的群列表，选择需要开放的群，再保存总开关、参与模式、人设和安静时段。**新部署、升级后的首次配置和新加入的群均默认关闭**；总开关只控制明确选择过的群，不会一键授权所有群。

- **仅 @ 回复**：普通消息不触发自由对话判断；`@`、`/ai` 和私聊照常使用。
- **少言**：回应直接喊机器人称呼、引用它的消息或自然追问，不主动加入旁人的话题。
- **自然／活跃**：结合短期聊天内容判断是否值得接话，也会选择等待或保持安静。每群独立限频，没人接话时降低打扰。

自由对话使用已有聊天模型，不用额外填写接口；只有已开启的群会产生额外判断和回复调用。普通文字会合并处理，不是每条消息都调用模型或保证回复；判断选择沉默、调用失败也会计入判断额度。当前只处理文字，不会自主调用联网、文件或改图工具；这些功能仍通过明确提问使用。安静时段仅限制自由对话，不拦截主动提问。人设决定语气和兴趣，不能扩大群权限或替代参与判断。

同一个群里，大家共享近期讨论和已有群记忆，机器人会结合不同成员的补充、反驳和追问接话。同一话题可以合并回应，普通公共讨论直接在群里发言，明确点名或引用追问时保留引用。自由对话与 `@` 都能看到同群已确认发送的机器人回答，并沿用同一称呼、人设和记忆库。

任务执行仍按成员隔离：有人 `@` 请求翻译时，其他人的闲聊和提问可继续；另一人的“继续”不能接管他的文件或操作。普通文字、表情和机器人自己的消息不会反复打断当前回复。近期公共上下文有上限，最多保留启用后最近 20 分钟、120 条、12000 字符；重启会清空这段缓存，已有长期记忆仍保留。自由对话只做受限的只读记忆召回，记住、更正、忘记仍通过明确提问完成。

每群及整个实例最多同时调用 2 路自由对话模型，等待发言间隔不占用模型名额；正常 `@` 任务另有默认 2 个前台处理名额，等待工具时会让出名额，最多保留 2 个工具等待任务。发言间隔和群预算仍然共享，并行不会把额度按人数翻倍。活跃参与每群最多判断 240 次／小时、2400 次／24 小时，最多回复 60 次／小时、600 次／24 小时；各群共用 4800 次／24 小时的判断额度。排队和发言间隔可能带来短暂延迟，是否接话仍由上下文决定。

`@` 请求正常排队或处理时不会主动发送等待提示；队列已满、处理失败或超时仍会给出反馈。需要了解进度时，可以在原群发送 **`@机器人 任务状态`** 或 **`@机器人 取消任务`**，这两项不排在长任务后面，只查询或停止你自己的会话请求。已发送内容不会撤回；已提交的文件、漫画后台任务或上游操作可能仍在运行，需要按对应任务状态处理。

机器人称呼用于判断群友是否在直接叫它；仅在别人的话里提到名字不代表一定要回复。管理页会显示此群实际生效的状态、参与额度及最近一次判断原因，便于区分正常沉默、冷却、正在处理提问和接口失败。

关闭总开关或群参与模式后，会取消尚未发送的任务并清理对应短期上下文；已交给 QQ 的消息无法撤回。预算记录随数据卷保存，重启不会重置额度。具体频率和上下文边界见 [功能说明](docs/FEATURES.md)。

上传文件、公开下载和处理产物使用共同的文件登记与任务流程，可以接着读取、检索、提取压缩包成员、生成附件并发送。现有 `QQTextReader` 插件身份保留，升级时无需再手装一个文件插件。无需重新翻译就能把已有译文保存为 TXT；图片翻译可直接选取已收到的图片，不必先手动打包。

主要边界：群历史默认按需查看提问前最近 24 小时、最多 1000 条，分批交给模型；设置页可调整为 1–168 小时、100–1000 条。多图编辑最多 4 张；公开下载和生成文件单个最多 20 MiB，通用附件每轮最多发送 5 个，旧网页直发入口另限 2 个；漫画输入最多 40 MiB、100 张图片。PDF 只提取已有文字，扫描页会标记需要 OCR；读取网页不执行 JavaScript。对话最多 24 轮工具迭代，能在预算内继续处理或换来源，不能无限重试。完整格式、任务和存储限制见 [功能说明](docs/FEATURES.md)。

## 日常管理与更新

| 操作 | Windows | Linux |
| --- | --- | --- |
| 启动 | 双击 `Start-Bot.cmd` | `bash bot.sh up` |
| 打开设置 | 双击 `Open-Bot.cmd` | `bash bot.sh url`，再打开完整链接 |
| 停止并保留数据 | 双击 `Stop-Bot.cmd` | `bash bot.sh down` |
| 查看状态 | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Public-Bot.ps1" -Action status` | `bash bot.sh status` |
| 查看日志 | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Public-Bot.ps1" -Action logs` | `bash bot.sh logs` |
| 按本地源码重新构建（开发用） | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Public-Bot.ps1" -Action rebuild` | `bash bot.sh rebuild` |

**容器部署的更新入口在设置页“版本更新”。** 检查版本后可查看目标提交，点击更新时固定到该 SHA；系统会构建候选镜像、备份并校验五个业务数据卷，再重启并检查服务。失败时尝试恢复备份和旧镜像，结果会显示在页面。ZIP 下载的部署同样可用，无需在本机执行 `git pull`。可更新的版本必须已发布到远端仓库；本机尚未提交或推送的修改不会出现在版本检查中。

网页更新管理容器镜像和数据卷，**不覆盖电脑上的源码目录**。普通启动会恢复已启用的部署版本，避免网页更新后被旧下载目录降级；只有显式 `rebuild` 才按本地源码重新构建。自己的源码修改不会自动合并进官方新版本；维护分支或插件时，先阅读[运维说明](docs/OPERATIONS.md)。更新期间机器人会短暂离线，先完成或取消长任务，不要执行停止命令。若 QQ 要求重新验证登录，更新后仍需在设置页扫码确认。

备份保存在独立 `update-data` 卷。更新器空闲时自动清理超出保留数量的成功更新记录，默认保留最近 **2 次成功更新的备份**及其恢复所需镜像；当前版本、仍被容器使用的镜像和失败／未完成／无法确认归属的记录会保留，不删除 QQ 登录、配置、记忆等业务卷。备份含私有数据，仍需另行保存重要备份；清理边界和构建缓存维护见[运维说明](docs/OPERATIONS.md#更新历史与磁盘清理)。

账号、密钥、QQ 登录、聊天、记忆和任务保存在私有 Docker 数据卷中。正常停止不会删除它们。**不要用 `docker compose down -v` 更新或排障**。独立 updater 容器需要 Docker socket 来备份、构建和替换服务；聊天服务、插件与配置向导均不直接获得该权限。首次启动和网页更新会执行你配置的代码仓库，请只使用自己信任的来源。

这是对成熟框架的集成与定制，包含 **1 个基于官方源码的 Agent、2 个定制插件、4 个原创插件**。架构和修改位置见 [架构说明](docs/ARCHITECTURE.md)，构建细节见 [Compose 部署说明](deploy/compose/README.md)。

## 目录导航与开发

| 目录／入口 | 用途 |
| --- | --- |
| `Start/Open/Stop-Bot.cmd`、`bot.sh` | 新用户启动与日常管理 |
| `bootstrap/` | 设置网页、首次初始化与统一 AI 配置 |
| `deploy/compose/`、`deploy/updater/` | 容器构建、固定来源与版本更新服务 |
| `custom-plugins/` | 六个本地维护的插件源码；官方 LocalAgent 在构建时获取 |
| `qunling/` | 跨插件共享的文件、任务、下载与产物基础；不依赖运行缓存 |
| `scripts/` | [维护工具](scripts/README.md)、旧原生配置与合成验证 |
| `config/`、`patches/` | 通用对话风格与可重放的框架补丁 |
| `docs/`、`tests/` | 使用／架构说明与离线回归 |
| `licenses/` | 第三方许可与来源记录 |


- 修改回答风格：`config/chat-style.txt`；显式 `rebuild` 后自动应用。
- 修改功能：通用文件与任务能力维护在 `qunling/`，QQ 和模型适配维护在 `custom-plugins/`；运行对应测试，再使用 `rebuild`。不要编辑运行缓存。
- 新环境优先使用容器。`scripts/Configure-*.py` 和 [Linux 手动部署](deploy/linux/README.md) 保留给已有环境维护，不是新用户的安装步骤。
- [贡献与验证说明](CONTRIBUTING.md) 包含测试入口、发布检查与兼容边界。

GitHub Actions 分别检查公开源码、实际 Linux 镜像内的插件与文件任务，以及全新数据卷初始化和更新恢复。测试使用合成资料，不登录 QQ、不调用付费模型，以对应提交的实际运行结果为准；新增能力的离线通过不能代替该版本的 Linux 部署验收。聊天、看图、改图、文件和漫画任务仍应结合自己的 AI 服务与 QQ 账号验收。
