# 本地图片生成和编辑扩展

当前本地版本为 `0.1.7-local.9`，基于官方 AIImagePlugin 0.1.6（`upstream-source.json` 记录精确版本）定制。该目录不包含密钥，也未向插件市场发布。

## 使用

- 私聊中用自然语言表达生成新图或修改图片的意图；不要求固定句式。
- 群聊遵守现有触发规则；已开启自由对话的群支持自然发起绘图和动画请求，无需再次 @。
- 新图由 `generate_image` 工具生成；修改图由 `edit_image` 工具编辑。
- 两个工具可用 `gif_frames` 指定 2–6 段动作/表情描述，`frame_duration_ms` 指定每帧停留 100–1500 毫秒（默认 350）。一次生图/编辑请求绘制等格分镜，再拆成独立图片合成循环 GIF，不使用视频生成模型。生成时约束角色、画风和镜头一致；实际连贯性和格子对齐仍取决于生图结果。
- GIF 分镜、拆出的帧和制作方案保存在同会话文件工作区，默认保留 7 天，随文件服务的空间限制和过期清理管理。后续改速度、顺序、字幕可以复用素材，交给 `gif_animation`，无需再次生图。
- GIF 合成与交付使用后台文件任务，返回 `task_id` 可由 `file_task` 查询。`queued/started` 不等于已经发送，不能重复发图；中途失败返回已保存的素材引用，不自动重复计费。
- 修改图优先使用本条消息或引用消息中的单张图片；否则使用同一机器人、会话和发送者最近的图（用户上传或本插件已发出的结果）。
- 明确要求组合两张图、交换两个角色的服装或多图参考时，可以选择 1–4 张图片，提交一次编辑请求并返回一张图，不要求先制作拼图。
- `list_edit_image_references` 按需列出当前/引用图片、同一发送者过去 30 分钟的上传与已发送结果，以及本群提问前默认 24 小时内最多 1000 条消息中的图片。统一设置页可调整近期群聊范围，并同步插件的 `history_hours`（1–168，默认 24）和 `history_max_messages`（100–1000，默认 1000）。实际可用记录取决于 QQ 与读取预算；仍只保留最多 24 张候选图，选中 1–4 张后才下载，截断状态会随结果返回。支持另一位群友发图后由提问者要求编辑；私聊不读取别人的图或其他会话。
- 工具只返回本轮 `edit_ref_*` 编号与消息、相对时间、说话人等资料，模型按用户意图选择。目标存在歧义时再简短确认，不自行拿最近一张替代。
- `edit_image` 可选参数 `image_refs` 接受本轮列表或当前图片提示已展示的 1–4 个不同编号；顺序与描述中的“参考图 1、参考图 2”对应。不传编号时保留原有单图行为。
- 这里的 `edit_ref_*` 与 QQGroupContext 的 `img_*` 独立；群聊识图工具中的编号不能直接作为编辑参考，需先列出编辑参考图。
- 引用内容无法读取时不会回退旧图；请重新引用或补发。若本条消息直接附有唯一图片，则优先使用这张直接附图。
- 同群历史候选由本轮可信消息锚点读取，排除提问后的新消息；普通群图片不需要先 @ 机器人。不可读取的图片附件会在列表中单独说明，不隐瞒失败或替换成其他图。
- 图片直接回复原会话，模型只获得操作状态；不以 Markdown 图片链接代替回图。
- 成功状态确认图片已生成并发送，不代表模型已检查成图像素。机器人可以说明本次要求和此前实际观察到的原图特征，但不会把生成提示词当作“成图已保留这些特征”的验证结果，也不应因此否认此前看图或发图。
- 保留 `!draw <描述>` 命令，其触发仍受现有流水线规则约束。

## 配置

| 字段 | 本地默认值 |
| --- | --- |
| `api_base_url` | `https://api.openai.com/v1` |
| `openai_api_key` | 留空；在插件设置中填写，使用 secret 输入框 |
| `model_name` | `gpt-image-2.5-sunburst`，可自由填写 |
| `image_size` | `1024x1024` |
| `quality` | `auto` |
| `request_timeout_seconds` | `300`，允许 30–300 秒 |

生成使用 `/images/generations`；编辑使用 `/images/edits` JSON `images:[{image_url:dataURI}, ...]`，单次包含 1–4 个参考。每个请求只生成一张，优先读取 `b64_json`，也兼容服务返回 HTTP(S) 图片 URL。所有参考图必须先读取成功，任何一张失败都不会提交部分参考或改为文生图。

## 生命周期与限制

- API 无自动重试；生成/编辑工具对同一用户消息共用一次调用标记，防止模型重复调用导致重复计费。超时不会声称上游已取消，服务可能仍在生成或计费。
- 单张图片上限 10 MiB，为 Base64 编码和 Runtime 16 MiB 消息封装预留空间。下载参考图单独设置超时、总字节限制，不向图片 URL 附加 API 密钥。
- 短期图像缓存按可信安装、工作区、机器人、会话和发送者隔离，TTL 30 分钟，最多 32 个 scope、总 64 MiB。每个 scope 只保留最新图，进程重启或过期后请补发/引用图片。
- 多图参考另外保留最多 64 条同人上传/已发送记录，以及最多 128 个本轮快照，每快照最多 24 张候选，内存图片总量上限 64 MiB。编号 TTL 15 分钟，绑定安装版本、query ID/UUID 与可信会话；不能复用其他问题的编号。重新安装或重启后需重新列出。
- 多参考下载共享 25 秒期限，单图上限 10 MiB，总 dataURI 上限 40 MiB；错误或未确认发送不自动重新提交。底层只使用 Python、SDK 和网络库，可在 Windows、Linux 运行。
- Query 变量只含 opaque 引用和状态，图片内容不进工具参数、模型工具结果或长期记忆。
- 不在插件代码、异常文字或日志中保存密钥或完整上游错误响应。不要开启 Host 原始 MessageChain 的 DEBUG 日志。
- 支持自然语言多参考编辑；不包含画笔蒙版或手动排版 UI。

## 失败提示与排查

- 提示“参考图片下载失败 / 下载超时 / 下载网络失败”时，失败发生在读取原图阶段，本次尚未提交图片编辑请求。HTTP 状态、总计 20 秒下载超时、无效格式或超过 10 MiB 会分别说明；可重新上传或引用目标图片。
- 提示“图片生成服务”时，已进入 API 请求阶段。认证失败（401）、权限不足（403）、接口或模型不存在（404）、请求过大（413）、限流或额度不足（429）、上游服务异常（5xx）会分别说明。400/422 默认提示检查参数兼容性。
- 只有上游 `error.code` / `error.type` 精确匹配已知内容拒绝码时，才说明“内容审核拒绝”；不根据错误正文猜测原因。上游错误正文只在内存中检查字段，不写入日志，也不向模型或 QQ 回传。
- 连接失败或生成超时不能证明上游未接收请求或未计费。所有阶段均不自动重试，同一用户消息仍只允许一次生成或编辑调用。
- 引用其他群成员的单张图可以编辑。原消息较早不等于缓存已过期：引用会作为本轮来源重新读取；若平台返回的图片链接失效，需要重新发送或引用图片。插件目前不自动向 QQ 刷新下载链接。

## 联网素材和动图参考

`edit_image` 新增 `asset_refs`，可直接接用联网图片、文件工作区、群图导入和前一步输出的共享图片；与原有 `image_refs` 二选一，范围仍限于当前授权会话。静态编辑可交付一张图片，改动图时使用 `gif_frames` 描述 2–6 个顺序动作。原 GIF 保持原样保存；发给模型/编辑接口的是带时间标签的采样关键帧，最多 6 帧，不是只传首帧或把原始 GIF 交给只理解静态图的接口。坏动图在提交付费编辑前报读取失败。

两个工具默认直接交付；若还要继续合成、排版或打包，可设置 `deliver=false`，把生成结果保存为共享素材。静态图返回 `asset_ref`，GIF 返回可查询的合成任务，完成后用任务结果中的素材引用继续处理。中间结果不会发到 QQ，也不会因为后续加工而再次生图计费。
