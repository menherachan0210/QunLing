# LongTermMemory 本地兼容修复

基于官方 `langbot-team/LongTermMemory 0.2.7`，本地版本为 `0.2.7+local.2`，用于当前 LangBot 4.11.0 部署。author/name 保持不变，以保留原安装身份、知识库绑定和插件存储。

## 修复原因

旧代码为抑制重复 RAG 检索，从 `_knowledge_base_uuids` 删除记忆知识库。LangBot 4.11 同时用这个变量判断知识库访问权限，因此插件随后自己的自动回忆、remember 和 recall_memory 会认为知识库没有绑定。

本地修复保留 Host 已授权的知识库集合，不增加任何授权，不改 LangBot 的权限检查；快照中的 `naive_rag_suppressed` 如实记录为 false。当前 LocalAgent 的普通 RAG 与记忆注入可能重复检索，属于此兼容修复的已知代价。

第二个问题是删除语义：Host 的 `file_ids` 指元数据中的 `file_id`，旧插件却传入向量主键，且没有写入对应元数据，导致工具声称删除但记录仍存在。本地版为新增/导入记忆保存 `file_id`，删除时同时限定 `user_key` 与 `file_id`，并重新读取确认目标已经消失。旧记录先在当前会话范围内找到，必要时使用本地 embedding 为该目标补齐标识，再删除；没有匹配时不声称成功。健康检查的临时记录也改为按其独有 `user_key` 清理。

## 验证

在本目录运行：

```powershell
& ..\..\langbot\.venv\Scripts\python.exe -m pytest tests -q --asyncio-mode=auto --disable-warnings
```

本次 92 项测试通过。新增测试复现旧版注入器撤销自身访问权限的问题，并验证修复后自动回忆、记忆写入/检索可用，以及未绑定的知识库仍被拒绝。删除测试连接独立临时 Chroma，经过真实 Host 删除分支，验证单条实际删除、跨会话隔离、旧记录兼容、健康探针完整清理，以及拒绝把虚假成功计数当成删除完成。测试不调用外部模型或 QQ。

## 重新打包与安装

在本仓库根目录（README.md 所在目录）运行：

```powershell
& .\langbot\.venv\Scripts\python.exe .\custom-plugins\Build-LongTermMemory.py
```

生成 `custom-plugins/LongTermMemory-0.2.7+local.2.lbpkg`。在 LangBot 插件页面选择“本地安装”，上传此包；也可使用已经登录的本地管理 API，向 `POST /api/v1/plugins/install/local` 提交 multipart 字段 `file`，随后查询返回的 `task_id`：`GET /api/v1/system/tasks/{task_id}`。

安装会替换同 author/name 的插件版本，无需卸载或删除数据。不要直接编辑 `data/plugin-runtime/artifacts/sha256` 中的只读缓存。

## 版本与后续升级

实际 SDK 接受 `0.2.7+local.2`；当前插件版本比较为字符串相等，并非完整 SemVer 优先级排序。安装来源为 local 时，当前 Host 的市场升级方法会拒绝升级该插件；未发现默认自动升级入口，因此无需更改全局配置。

以后手动从市场重新安装官方版本可能覆盖此修复。升级前检查官方是否已经分离“检索抑制”和“授权范围”，并重新执行记忆健康检查及实际写入、清空短期上下文后回忆、删除后查看向量记录的验收。当前完整插件补丁为 `patches/longterm-memory-compatibility.patch`，包含授权与删除两项修复；旧 `longterm-memory-pipeline-authorization.patch` 仅对应 local.1，不要重复叠加。
