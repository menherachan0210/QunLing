# LongTermMemory 本地兼容修复

基于官方 `langbot-team/LongTermMemory 0.2.7`，本地版本为 `0.2.7+local.3`，用于当前 LangBot 4.11.0 部署。author/name 保持不变，以保留原安装身份、知识库绑定和插件存储。

## local.3：自由对话共享只读记忆

QunLing 仅在决定参与讨论之后请求 `include_profiles=True`，从已绑定的记忆知识库读取同一个机器人、同一个真实 QQ 群的记忆。检索最多返回三条，优先保留当前回复对象的成员画像、群画像和一条相关情景；没有画像时，空出的名额用于情景记忆。每条保留成员归属，群画像单独标记；不读取这个人在其他群或私聊中的画像，也不遍历同群其他成员的画像。

画像读取先于 embedding，每个画像读取最多等待 0.35 秒，随后情景检索最多等待 1.5 秒。embedding 冷启动、异常或尚未配置时，已读出的画像仍可返回；某个画像读取失败不妨碍另一个画像与情景记忆。Host 对整个召回另设三秒总期限，并限制输入和输出大小、复核授权及来源、过滤内部附件引用和明显凭证。

这个选项只读，不修改画像、情景记忆、候选提取、记忆写入策略或知识库配置。未提供 `include_profiles=True` 的现有 @ 请求保留原来的情景检索和画像注入行为，不重复追加此处的画像。

## 修复原因

旧代码为抑制重复 RAG 检索，从 `_knowledge_base_uuids` 删除记忆知识库。LangBot 4.11 同时用这个变量判断知识库访问权限，因此插件随后自己的自动回忆、remember 和 recall_memory 会认为知识库没有绑定。

本地修复保留 Host 已授权的知识库集合，不增加任何授权，不改 LangBot 的权限检查；快照中的 `naive_rag_suppressed` 如实记录为 false。当前 LocalAgent 的普通 RAG 与记忆注入可能重复检索，属于此兼容修复的已知代价。

第二个问题是删除语义：Host 的 `file_ids` 指元数据中的 `file_id`，旧插件却传入向量主键，且没有写入对应元数据，导致工具声称删除但记录仍存在。本地版为新增/导入记忆保存 `file_id`，删除时同时限定 `user_key` 与 `file_id`，并重新读取确认目标已经消失。旧记录先在当前会话范围内找到，必要时使用本地 embedding 为该目标补齐标识，再删除；没有匹配时不声称成功。健康检查的临时记录也改为按其独有 `user_key` 清理。

## 验证

在本目录运行：

```powershell
& ..\..\langbot\.venv\Scripts\python.exe -m pytest tests -q --asyncio-mode=auto --disable-warnings
```

local.2 当时的 92 项测试覆盖注入器保留授权、记忆写入/检索、未绑定知识库拒绝，以及通过独立临时 Chroma 验证的删除语义、跨会话隔离和健康探针清理。

local.3 的新增回归在 `tests/knowledge_engine/test_group_profile_recall.py`，验证真实 MemoryStore 的同群/当前成员画像读取、三条总预算、默认 @ 行为不变、空画像、存储损坏、画像读取超时及 embedding 异常/冷启动时的分阶段降级。仓库根目录的 `tests/test_group_memory.py` 和 `tests/test_group_dialogue_integration.py` 验证 Host 授权、来源检查、取消、跨成员话题与附件边界。测试不调用外部模型或 QQ。

## 重新打包与安装

在本仓库根目录（README.md 所在目录）运行：

```powershell
& .\langbot\.venv\Scripts\python.exe .\custom-plugins\Build-LongTermMemory.py
```

生成 `custom-plugins/LongTermMemory-0.2.7+local.3.lbpkg`。在 LangBot 插件页面选择“本地安装”，上传此包；也可使用已经登录的本地管理 API，向 `POST /api/v1/plugins/install/local` 提交 multipart 字段 `file`，随后查询返回的 `task_id`：`GET /api/v1/system/tasks/{task_id}`。

安装会替换同 author/name 的插件版本，无需卸载或删除数据。不要直接编辑 `data/plugin-runtime/artifacts/sha256` 中的只读缓存。

## 版本与后续升级

实际 SDK 接受 `0.2.7+local.3`；当前插件版本比较为字符串相等，并非完整 SemVer 优先级排序。安装来源为 local 时，当前 Host 的市场升级方法会拒绝升级该插件；未发现默认自动升级入口，因此无需更改全局配置。

以后手动从市场重新安装官方版本可能覆盖此修复。升级前检查官方是否已经分离“检索抑制”和“授权范围”，并重新执行记忆健康检查及实际写入、清空短期上下文后回忆、删除后查看向量记录的验收。`patches/longterm-memory-compatibility.patch` 保留 local.2 的授权与删除修复历史；它不是当前运行时安装来源，也不包含 local.3 的只读画像选项。当前构建以本插件目录源码与 manifest 为准。旧 `longterm-memory-pipeline-authorization.patch` 仅对应 local.1，不要重复叠加。
