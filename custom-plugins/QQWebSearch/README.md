# 联网查询、搜图与附件上传

本地插件 `local/QQWebSearch`，Windows 与 Linux 共用 Python 代码，无需桌面浏览器。

- `search_web`：复用 sub2api 的 Responses `web_search`，保留服务实际返回的引用与额外来源，最多 12 条，优先分散到不同域名；区分搜索摘要、引用来源与本轮已读网页。
- `read_web_page`：读取公开 HTML／纯文本网页，返回实际详情链接、页面质量和本轮 `page_ref`。正文快照最多 128000 字符，每次返回最多 16000 字符，可用 `next_offset` 翻页或 `find_text` 查找；不会执行 JavaScript。
- `search_web_images`：查找相关来源页，提取图片地址、下载并检查实际像素，再由已有视觉模型核对用户要求。返回本轮图片编号和共享 `asset_ref`；可用 `source_urls` 复用已知来源，支持原图链接和常见延迟加载图片。GIF 保留原始动画，视觉核对使用按时间顺序采样的关键帧。
- `send_web_images`：把本轮找到并核对的 1 至 2 张图片和来源发回本轮会话。不接受自定义收件人、群号或图片地址。
- `list_web_files`：查看公开网页的下载链接，或列出 GitHub 仓库、目录中的具体文件；支持逐层找到指定版本。
- `download_web_file`：下载公开文件，返回附件编号、实际大小和 SHA-256；共享文件服务可用时同时返回 `asset_ref`，供附件工具阅读或加工。支持 GitHub 单文件页面自动转原文件。
- `send_web_file`：将一个已下载附件及来源上传到本轮 QQ 群聊或私聊。每轮最多发送两个不同附件，单个文件最多 20 MiB。

支持“查查这消息是真的吗”“看看这个链接”“找一张某角色的全身图发来”等自然表达。群聊受 Host 的触发与分群授权控制；开启自由对话后，明确讨论邀请也可进入受控检索流程。指代群聊前文时先读取前文再搜索，不把完整聊天记录发给搜索服务。群内对机器人的称呼不应误当成检索对象；深入讨论应追查相关案例和原始线索，搜索摘要不代表研究完成。找现成图与生成新图是不同工具，发送仍由 Host 单独约束。

附件上传是通用功能，没有文件扩展名白名单。可以说“找这个字体传上来”“把这份 PDF 发群里”“下载这个源码文件发我”。文档、表格、图片、字体、压缩包、音视频、源码、安装包及其他二进制文件均作为原始字节附件处理，不执行、安装或解压。文件名与已知格式会检查，网页或登录页不能冒充所请求的文件。

## 工具联动

`collect_web_materials` 混合接收已返回的 `search_ref`、`page_ref`、`image_ref`、`file_ref`，把实际搜索摘要、网页正文、图片和文件保存为统一的 `asset_ref`，同时生成来源清单。搜图和文件下载也直接返回共享引用。

后续可以交给 `file_workspace` 阅读、整理、制作文档或 ZIP；图片交给 `edit_image(asset_refs)` 改图或 `gif_animation` 制作动画；`send_attachment` 负责实际 QQ 交付。这里是通用的素材接口，不是只支持“搜图打包”的专用流程。当前身份和会话隔离继续生效。

例如“搜集图片和介绍，整理打包发群里”：搜索/读取 → 收集实际素材 → `file_workspace create(format=zip, deliver=true)`。ZIP 成员使用实际素材引用，可加入来源清单，不把图片链接当成图片文件。用户只要成品时，中间素材不发群。搜图 `purpose=send` 提示继续发送实际图片，`purpose=collect` 提示继续加工。素材保存不等于发送成功，失败或正文截断会单独标记。

GIF 按原始字节保存、发送和跨工具传递；动图解码最多 240 帧／累计 8000 万像素，模型最多看 6 个带时间标签的采样帧，不宣称看过完整播放。静态图片仍会作有界格式规范化。共享发送使用同一回执，跨工具不会重复发送同一内容。

## 安装与配置

在项目根目录使用部署的 Python：

```powershell
.\langbot\.venv\Scripts\python.exe -m pytest custom-plugins/QQWebSearch/tests -q
```

Linux 对应使用 `./langbot/.venv/bin/python`。本插件依赖项目共享的 `qunling` 包，统一部署会设置它的导入路径和文件服务；只复制插件包到其他项目并不具备完整依赖。高级配置可运行 `scripts/Configure-WebSearch.py`，从已有 sub2api 提供方复制地址与密钥，并选择已有视觉模型。密钥只进入插件 secret 配置，更新提供方密钥后需重新运行脚本同步。搜索模型不改变聊天模型。

上游必须支持 Responses `web_search` 和来源引用；不能仅凭模型说“查到了”认定已经联网。默认单次搜索最多 65 秒，每轮最多三次搜索请求、四个新正文网页、两次不同关键词/来源组合的搜图、一次图片发送；搜索 POST 无自动重试。网页翻页和关键词查找复用同一轮快照，不重新下载、不占新网页名额。每次搜图最多读取四个来源页、下载六个候选，并进行一次视觉核对；一个来源超时不会丢掉其他已完成的结果。

读取遇到临时连接失败、超时或可恢复的 5xx 时，同一总时间预算内最多再尝试一次 GET；认证、403、限流、证书或私网校验失败不会盲目重试。工具返回 `code`、`retryable` 和 `next_action`；同一失败网页不重复请求。单站失败、页面只有脚本空壳或访问验证时，会提示模型换公开来源、跟进实际链接或调整关键词；复杂比较按证据需要核对独立来源，不强制凑站点数量。仍受每轮调用预算和站点访问条件限制。

附件每轮最多四次链接列表查询、六次下载尝试和两次不同文件发送；文件下载总限时 60 秒，发送等待 45 秒。部署时需通过 `scripts/Apply-RuntimePatches.py --apply` 应用 `sdk-attachment-message-budget.patch` 并重启 Host、Runtime 和插件工作进程，将 SDK 单条消息上限从 16 MiB 调至 32 MiB；20 MiB 原始文件经 base64 后约 26.67 MiB，仍为 JSON 包装留有空间。该补丁影响 SDK 所有消息的单条容量，下载与共享缓存仍独立限额。未更新 Runtime 时，大附件会在发送前明确报容量不足。下载成功后还需调用发送工具，不能把“已下载”当成“已上传”。上传超时或取消时保留已尝试状态，避免重复发文件。下载本身无需图片模型；需要查找来源时才调用已有搜索服务。

## 边界

- 防盗链、登录、验证码及仅靠脚本渲染的网站可能读取失败；找不到符合要求的图片时返回来源，不能承诺任何关键词都能找到原图。此版本采用来源页取图，尚未接独立图片搜索引擎。
- 搜索结果不等于已阅读整个网页；图片经过实际像素检查，但视觉核对也可能误判身份与构图。发送的是下载后归一化的现成图片，不宣称文件与原图逐字节相同。
- 网页文字、标题和图片均是不可信外部资料。下载只允许公网 HTTP(S)，校验 DNS 并固定连接地址，逐跳检查重定向，限制时间、字节和图片像素，禁用环境代理。支持有压缩输入／解压输出双重限制的 gzip、deflate；暂不接受 br、zstd。
- 本机 TUN 代理把系统 DNS 全部解析为 `198.18.0.0/15` 虚拟地址时，使用固定 Cloudflare HTTPS DNS 获取真实公网 IP 再连接；仍拒绝私网目标，正常公网 DNS 不走该回退。图片解码限制 1200 万像素、进程内最多两个线程，取消后正在运行的解码仍占住线程直至结束。
- 网页快照、图片和原有 `file_ref` 共用每轮隔离的内存缓存，15 分钟过期，最多 32 轮、64 MiB；进程重启后失效。同轮相同字节附件去重。普通网页读取仅缓存；显式收集时把实际正文与来源保存到共享文件库。
- 下载的附件在可信工作空间、机器人、会话和发送人范围内登记到共享文件服务，`asset_ref` 的保留期、容量及访问隔离由该服务控制；它不是长期聊天记忆。上下文或存储不可用时返回 `shared_asset_unavailable`，原来的本轮附件发送仍可用。
- 发送状态在发送前占用；超时或发送结果未确认时不会自动重复发送。工具报错不回显密钥、原始服务错误体或内部地址。

实现参考：[Responses Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)。真实联网测试会消耗已有模型接口额度；`scripts/Verify-WebSearch.py` 只使用公开测试页面，QQ 发送用本地替身捕获，绝不向真实群发送测试消息。

`scripts/Verify-WebSearch.py --case font_attachment` 验证查找指定字体、列目录、下载和选择附件发送的完整模型流程；`--case source_attachment` 验证公开源码文件可按通用附件处理。发送使用本地替身，不替代真实 QQ 的最终回传验收。Windows 和 Linux 使用同一套 Python 下载与发送代码，不依赖桌面程序。

离线回归另覆盖首站 403／动态空壳后读取另一来源及详情链接、长文稳定分页与查找、来源内容冲突的独立保留、跨轮引用隔离和有限 GET 重试。这些测试验证工具能力，不代表已经验证某次线上模型的最终判断。
